Agentic Research and Portfolio Maker

A Nifty 50 chat app with a guarded router and three agents (technical, fundamental, portfolio), plus an admin tab that shows token usage, speed and guardrail activity for every local model call through an AI gateway. Limited to the Nifty 50.

3. Guardrails

Guardrails are plain code, not LLM instructions, so a clever prompt can't talk its way past them. They run before the router, and the portfolio MCP server checks the same rules again inside its tools.

#RuleActionAlert shown to the user
G1Every stock must be in the Nifty 50 list (NIFTY_50.csv, 50 stocks)block"XYZ is not in the Nifty 50. This app covers only the 50 Nifty 50 stocks."
G2Portfolio has 4 to 6 distinct stocks. 7 or more is blocked; the same symbol twice counts onceblock"A portfolio can hold 4 to 6 stocks. You asked for 8. Choose up to 6, or I can pick the top 6."
G3Fewer than 4 stocks (my assumption, you only specified the upper limit)block"A portfolio needs at least 4 stocks. Add more, or let me suggest some."
G4Weights sum to 100%, each between a minimum and maximum (defaults 5% and 40%, adjustable)block"Weights must total 100% and each stay within 5% to 40%."
G5More than half the weight in one sector (industry group from nifty-50.csv)warn"58% of this portfolio is in Financial Services."
G6A stock has under one year of price history (TMPV has 276 days)warn"TMPV has only 276 trading days, so risk and backtest results are less reliable."
G7Every portfolio answer carries a "research tool, not investment advice" note, the data date and the unadjusted-price caveatnoteShown under the result
G8Limits per question: tool calls, agent loop steps, tokens (set in the gateway)stop"Stopped after 12 tool calls. Try a narrower question."

Every trigger is written to the usage log, so the Admin tab can show which rules fire most.

4. Portfolio agent

Two ways to start: you name the stocks ("make a portfolio of TCS, HDFCBANK, ITC, LT"), or you give a goal ("a low-risk 5-stock portfolio"). In the second case the agent scores candidates with the technical and fundamental tools, then proposes 4 to 6.

Tool (portfolio MCP server)What it does
validate_portfolio(symbols, weights)Runs G1 to G6 and returns pass, warnings or the block reason
suggest_portfolio(goal, n, risk)Picks n stocks (4 to 6) from the Nifty 50 using momentum, volatility and fundamental scores, spread across sectors
build_portfolio(symbols, method)Sets weights by equal weight, inverse volatility, risk parity, minimum variance or maximum Sharpe
portfolio_metrics(portfolio)Return, volatility, max drawdown, Sharpe, correlation matrix, beta against an equal-weight Nifty 50 proxy
sector_exposure(portfolio)Weight by industry group
allocate_capital(portfolio, amount)Whole shares per stock at the latest close, and cash left over
backtest_portfolio(portfolio, start, rebalance)Historical value with periodic rebalancing, with the price-adjustment caveat
compare_portfolios(a, b)Side-by-side metrics
swap_stock(portfolio, out, in)Replace one holding, re-checked by the guardrails
rebalance_plan(portfolio, drift)Trades needed to return to target weights
save_portfolio / load_portfolio / list_portfoliosKeep named portfolios between chats
Limits of the data: there is no Nifty 50 index price history on disk, only a one-day snapshot, so beta uses an equal-weight average of the 50 stocks as a stand-in. Prices are not adjusted for splits, bonuses or demergers, so long backtests can be off.

Example

You:    Build a portfolio of 8 stocks.
App:    [Guardrail G2] A portfolio can hold 4 to 6 stocks. You asked for 8.
        Choose up to 6, or I can pick the top 6.

You:    Add Tesla and Infosys to my portfolio.
App:    [Guardrail G1] Tesla is not in the Nifty 50. This app covers only the 50 Nifty 50 stocks.

5. AI gateway and tokenomics

Every call to Ollama, including embeddings during document loading, goes through one gateway function. Nothing talks to the model directly, so the log is complete.

What is recorded for each call

Ollama returns these numbers with every response (I confirmed this on your machine).

FieldSourceUse
Input tokensprompt_eval_countUsage and what-if cost
Output tokenseval_countUsage and what-if cost
Total time, load timetotal_duration, load_durationLatency, cold starts (the first call to a model loads it into memory)
Generation speedeval_count divided by eval_durationTokens per second per model
Who and whyAdded by the gatewaySession, agent, graph node, route, model, status, error, tool calls and their time
Guardrail eventsAdded by the guardrailsRule id, action (block, warn, stop), symbol or count involved

Cost for a local model

Ollama has no per-token fee, so a real dollar cost doesn't exist. The Admin tab shows tokens and time as the main measures, plus an optional what-if cost: tokens multiplied by a rate per million tokens that you set for each model. I won't pre-fill any prices.

Controls the gateway can enforce

  • Model allow-list, and which model each agent uses.
  • Timeout per call, and a maximum number of agent loop steps per question.
  • Token budget per question, per session and per day.
  • Retry once on failure, then a clear error instead of a hang.

Start as a Python wrapper inside the app. It can later become a small separate service, if other tools need to share it.

10. Build plan

Phase 1: foundation and technical agent

Python venv, AI gateway with usage logging, DuckDB over the 50 price files, market-data MCP server, technical LangGraph agent.
Done when: test questions give correct, dated answers, indicators match a reference calculation, and every LLM call appears in the usage log.

Phase 2: fundamentals, structured

Excel data into DuckDB, financial tools and the snapshot ratios from nifty-50.csv.
Done when: figures reconcile with the workbooks, with units and consolidated status shown.

Phase 3: document RAG, Tier 1 then 2 then 3

Extract, chunk, embed, index, and search_documents with filters and page citations.
Done when: answers cite file and page, and "no documents" is returned for gaps such as INFY.

Phase 4: guardrails, router and chat app

Guardrails G1 to G8 as code with tests, the router, the parallel "both" route, the synthesizer and the Chat tab.
Done when: a fixed list of test questions routes correctly and every guardrail case triggers its alert.

Phase 5: portfolio agent

portfolio MCP server, the agent, saved portfolios, and the checks repeated inside the tools.
Done when: 4 to 6 stocks work, 3 and 7 or more are blocked, non-Nifty 50 stocks are blocked, and metrics match a hand calculation.

Phase 6: Admin tab

Password-protected tab with the KPIs and charts above, request log, guardrail view and read-only controls.
Done when: totals in the tab match the raw usage log, and a budget limit visibly stops a run.
