IITKGP Agentic Stock Research

Hybrid Agentic RAG + MCP Architecture

A financial-intelligence platform combining document research, structured market data, reusable tools, and multi-step AI orchestration.

LangGraphHybrid RAGMCPPostgreSQLChromaDuckDB

1. Executive summary

StockWood combines RAG for company-document research, MCP for reusable tools and data capabilities, and LangGraph for planning, routing, orchestration, and validation. PostgreSQL, Chroma, and DuckDB provide the storage and query foundation.

Core principle
Downloaders acquire data; ingestion pipelines prepare it; databases store it; RAG retrieves knowledge; MCP exposes capabilities; LangGraph orchestrates the workflow.
  • RAG handles unstructured documents and contextual research.
  • SQL and analytical code handle exact numerical queries.
  • MCP is a protocol/interface, not a database and not a requirement for every component.
  • One primary IITKGP Agentic Stock Research agent can use multiple specialized tools.

5. Hybrid RAG engine

5.1 Semantic RAG for unstructured documents

Sources include annual reports, earnings-call transcripts, investor presentations, and other company research documents.

PDF / transcript / presentation
↓
Text extraction / OCR
↓
Cleaning + metadata + document-aware chunking
↓
Embedding model
↓
Chroma vector database
↓
Metadata-aware retrieval + source citations

Metadata should include company, document type, financial year/reporting period, publication date, filename, page/section, chunk ID, and ingestion version.

Example questions
  • What are the key business risks in the annual report?
  • What did management say about customer acquisition costs?
  • How has management guidance changed across reporting periods?
  • What are the company's expansion plans?

5.2 Structured financial retrieval

Screener Excel files contain numerical information. Exact financial queries should use SQL and deterministic calculations, not vector similarity alone.

Screener Excel files
↓
Pandas / Excel processor
↓
Financial data normalization
↓
PostgreSQL structured tables
↓
SQL / Python calculations

Examples: revenue by financial year, five-year revenue CAGR, debt-to-equity filters, ROCE trends, and quarterly growth. Preserve units, reporting periods, consolidated/standalone distinctions, and provenance.

5.3 RAG as an agent capability

LangGraph can call the retriever directly as a Python tool. MCP is not required for RAG.

@tool
def search_company_documents(
    company: str,
    query: str,
    document_type: str = "all"
):
    # Search company reports, presentations and transcripts.
    return rag_retriever.search(
        company=company,
        query=query,
        document_type=document_type
    )

The same capability can later be exposed through a Fundamental Research MCP server if external MCP clients need access.

6. MCP tool architecture

Organize MCP servers around business capabilities, not individual files or downloaders. Start with two servers and optionally add a third.

6.4 MCP-to-database communication

LangGraph Agent / MCP client
↓
Market Data MCPPython business logic
Index Data MCPPython business logic
↓
PostgreSQL

Example: the agent calls get_stock_price(symbol, date); the MCP server validates inputs, runs a parameterized SQL query, returns structured data, and the agent explains the result and its date.

MCP is not a database. MCP exposes functions. Python implements business logic. PostgreSQL executes SQL and stores records. The MCP server returns results to the agent.

Transport and FastAPI

  • STDIO: suitable for local MCP processes.
  • Streamable HTTP: suitable for remote MCP services.
  • FastAPI: optional for REST endpoints, authentication middleware, and other application APIs.

An MCP server can run without FastAPI.

12. Implementation roadmap

PHASE 1

Data foundation

  • Inspect representative Excel, Bhavcopy, and index CSV files.
  • Confirm schemas, dates, symbols, units, and field meanings.
  • Design PostgreSQL tables and indexes.
  • Load historical data and build incremental ingestion.

Exit: deterministic queries and source-to-database reconciliation.

PHASE 2

RAG engine

  • Integrate Screener documents.
  • Implement PDF and Excel processing.
  • Add metadata-aware retrieval.
  • Implement structured financial retrieval.
  • Validate numerical accuracy and citations.

Exit: grounded document answers and validated numerical results.

PHASE 3

MCP servers

  • Implement Market Data MCP.
  • Implement Index Data MCP.
  • Test tools independently.
  • Add optional Research MCP if needed.
  • Add access controls and logging for remote deployment.

Exit: MCP clients invoke documented tools and receive structured results.

PHASE 4

LangGraph agent

  • Implement planner and router.
  • Add RAG and MCP routing.
  • Implement multi-tool execution.
  • Add validation, error handling, and response generation.
  • Track calls, latency, and provenance.

Exit: multi-source questions use correct tools and traceable evidence.

PHASE 5

StockWood UI

  • Chat and research reports.
  • Stock screening dashboard.
  • Technical charts and fundamental analysis.
  • Source citations and execution logs.

Exit: end-to-end research workflows through the application.

13. Security, reliability, and financial-data controls

  • Keep screener_auth.json out of Git, container images, and logs.
  • Use environment secrets or a secret manager.
  • Use read-only database credentials for analytical MCP tools.
  • Use parameterized SQL; do not expose unrestricted SQL execution to the LLM.
  • Validate symbols, dates, periods, and query limits.
  • Track source filename, source date, ingestion time, and processing version.
  • Make ingestion idempotent and support retries.
  • Identify missing trading dates and incomplete source files.
  • Distinguish unavailable data from zero values.
  • Preserve document page/section references and financial reporting periods.
  • Include data freshness in responses.
  • Do not describe historical Bhavcopy data as real-time market data.
  • Test calculations, joins, symbol mapping, and index membership history.

Final design principle

Downloaders acquire data. Ingestion pipelines prepare data. PostgreSQL, Chroma, and DuckDB store and query it. RAG retrieves knowledge. MCP exposes reusable capabilities. LangGraph orchestrates the complete workflow.

IITKGP Agentic Stock Research should be built as a multi-source financial-intelligence agent, not merely a chatbot connected to a vector database.
