3. Target architecture

Streamlit app: Chat tab (answer, sources, data date, alerts) and Admin tab (tokens, speed, guardrail events, and Model settings: provider and model per role, chunking, re-index, audit log)

↓

Guardrails (plain code): Nifty 50 only, 4 to 6 stocks, weight limits, call and token budgets. Run before the router and again inside the portfolio tools.

↓

Prompt enhancer (prompt_enhancer.py, slim): resolves company names to Nifty 50 symbols and relative dates in plain code, rewrites follow-up questions with one short LLM call only when needed, and asks the user a clarifying question instead of guessing. No generic LLM rewriting. The original question stays visible.

↓

LangGraph router (one LLM call): technical | fundamental | research | portfolio | both | out of scope. Then a synthesizer that merges results and adds citations.

↓

scorecard.py (code, cached)

↓

financials, growth, ratios, document search
MCP: fundamentals

Call chain. portfolio manager → research analyst → technical and fundamental agents. Maximum depth 3. Each child call gets a share of the parent's step and token budget. The gateway logs a parent call ID, so the Admin tab can show who called whom. Plain numbers always come straight from tools, not from nested LLM calls.

↓

AI gateway (built, 21 tests pass): every model call (chat, embeddings, judge) passes here. Callers name a role, never a provider. The gateway reads the saved settings on every call, picks the provider, retries once, counts tokens, times each call and writes the usage log. Switching provider is a setting, not a code change, and a test fails if any file other than providers.py calls a model service.

5. Model settings in the Admin tab

Requested 19 Nov. The Admin tab changes from read-only to a control panel. Settings live in SQLite with an audit table (who, when, old value, new value), and the gateway reads them on every call.

RoleWhat it doesDefault
Chat / agentsAgents and the synthesizerOllama mistral:7b
RouterPicks the routeOllama mistral:7b
EmbeddingVectors for chunks and queriesOllama nomic-embed-text
RetrievalTop-k, filters, optional rerankertop-k 8, no reranker
SummarySummarizes retrieved passages and long documentsOllama mistral:7b
LLM as judgeScores answers: groundedness, relevance, citation checkOllama gemma4:12b
ChunkingStrategy: size, overlap, split by page or section1000 characters, 15% overlap

Providers per role: local Ollama, Hugging Face, or an external OpenAI-compatible API (base URL and API key).

PointWhat it means
note "Chunking model"nomic-embed-text is the embedding model. Chunking is a strategy (size and splitting), not a model. Both are separate settings.
re-index Changing the embedding model or chunkingStored vectors no longer match. One Chroma collection per embedding model and chunk setting; keep the old one until the new one is complete. Tiers 1 to 3 take about 1.3 to 1.6 hours locally. The tab shows an estimate and asks for confirmation.
privacy External providersQuestions, document text and answers leave the machine, so the "fully local" rule no longer holds for that role. Off by default, opt-in per role, with a visible warning.
API keysFrom environment variables or config/arpm.env (mode 600). Never stored in SQLite, never logged, only the last 4 characters shown.
CostExternal calls cost money per token, so the what-if cost view becomes real cost, using rates the user enters. No prices pre-filled.
SafetyAdmin password required. "Test connection" runs one small call before saving. Unknown models are rejected. Allow-list, timeouts and budgets apply to every provider.
Judge independenceThe judge model should differ from the model that wrote the answer. The tab warns if they match.
Token countsOllama reports exact counts. Other providers differ. The gateway normalizes them and marks estimated counts.
