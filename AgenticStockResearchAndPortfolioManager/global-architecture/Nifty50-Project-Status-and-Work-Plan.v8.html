Principles that the code enforces. (1) Numbers come from tools (DuckDB, Excel data), never from the model and never from vector similarity. (2) An agent that answers without calling any tool is reminded once, then replaced by a "no tool data" message. (3) Every document-based answer cites file and page. (4) A collection is searched only after it is marked complete. (5) Nothing is deleted: old files are kept under versioned names, and the UI has no delete button. (6) The research analyst may not add a number or a page citation that neither specialist gave. (7) A rate is never guessed: an external call with no rate is shown as unpriced.

3.1 Traffic flow: chat app, router, agents, tools, gateway

This is the path one question takes. Every arrow is a real function call in the code today. Colours as in the legend above: purple calls a language model, green is plain code.

1. Chat app (ui_app._ask()). Saves the question to chats.sqlite, shows it, then takes the global lock _CHAT_LOCK and shows "Working...". One question runs at a time, because the agents are shared objects that keep per-run state.

↓ answer(question, conversation_id)

2. Router (router.route()). Keyword rules, plain code, no model call. Returns documents, portfolio, news, fundamental, technical or both. Order of the rules:
  1. a documents word (annual report, transcript, concall, capex, attrition...) gives documents;
  2. a portfolio word (portfolio, rebalance, asset allocation, basket of stocks) gives portfolio;
  3. a news word (news, headline, sentiment, announcement, latest on, in the news, buzz, rumour...) alone gives news; with a price or statement word as well it gives both (a documents or portfolio word still wins);
  4. a statement word (revenue, ROE, P/E...) or a Screener word (PE, OPM, NPM, promoter, FII, PEG...) marks it fundamental. Next to a Screener word, RSI and MACD are not counted as technical, because the Screener table carries them;
  5. a fundamental and a technical word together give both;
  6. no such word, but an open request (research, should I invest, cheap, tell me about...) or a comparison (compare, vs) gives both;
  7. otherwise fundamental if marked, else technical (also the default when nothing matches).

↓ route name

portfolio
one agent: agent_portfolio_manager (mcp_portfolio.py: scorecard, suggest, build, evaluate; guardrails G1 to G7 run inside the tools)
news
one agent: agent_news (mcp_news.py: news_search, news_sentiment, news_market)
technical
one agent: agent_technical
fundamental and documents
one agent: agent_fundamental. A documents question differs only in which tool the model picks (rag_search_documents).
both
ResearchAnalyst.run(), which calls the technical, fundamental and (when asked about news) news agents. Saved with route label research.

↓ each agent runs the loop in 4.2, calling tools in its own MCP server and the model through the gateway

3. Back in the chat app. answer() returns text, tool trace, budget, stop reason and route. The app saves the assistant message, shows it, and reruns the page so the sidebar lists the conversation. An exception is caught and shown as "I could not answer this: ...", never a blank page.

3.2 How the research analyst works with the technical and fundamental agents

The analyst is a coordinator. It has no tools and no data access of its own, so it cannot produce a number itself. It owns two model calls (split, merge) and borrows the two specialists, which already exist and are reused unchanged. The same TechnicalAgent and FundamentalAgent objects serve single-topic questions and the analyst.

ui_app.answer() gets both and calls research.run(question, session). One Budget is created: 24 model calls, 40 tool calls, 80,000 tokens. It is passed to everything below, so the whole question is capped, not each agent.

↓

A. Split — gateway role chat, node split, temperature 0. Output: JSON {"technical": "...", "fundamental": "..."}. Each part repeats the stock names, so each reads on its own. A part is empty when not needed.

↓

Both parts present
run technical, then fundamental, one after the other
One part empty
run that agent only. Its answer is returned as it is. No merge call (saves a model call).
Split call failed or JSON unreadable
run both agents on the whole question, each told "answer only your half"

↓

B1. agent_technical.run(part)
loop of 4.2 → tools in mcp_market_data (10 tools: quote, OHLCV, returns, 52-week, delivery, indicators, compare, movers...) → DuckDB arpm.duckdb
B2. agent_fundamental.run(part)
loop of 4.2 → tools in mcp_fundamentals (11 tools: 7 fsa_* statement tools, 3 screener_* snapshot tools, 1 rag_search_documents) → fundamentals.duckdb, screener.duckdb, Chroma

↓ each returns answer, tool trace and any stop reason. A failed or stopped specialist reads "Not available: reason" and does not stop the other.

C. Merge — gateway role chat, node synthesis. Input: the question and the two answers (each cut to 6,000 characters). Rules: use only numbers and facts in the two answers, keep document citations next to their point, never write a page for the analysts themselves, for a buy or sell question say it cannot advise and give evidence for and against, group by stock.

↓

Citation check
strip_unsupported_citations removes any bracketed page citation neither specialist wrote
Number check
unsupported_numbers: a number in the merged text that is not in the question or either answer (whole numbers up to 10 are ignored) → the merged text is dropped
Fallback
the two labelled specialist answers are shown as they are, with a note under the answer

3.5 Known gaps in this traffic flow

  • No compare or out-of-scope route. A portfolio route now exists (checked 26 Nov: agent_portfolio_manager.py, mcp_portfolio.py, ui_app.answer() and tests are in place; a live run is still to be recorded). A compare question still falls into both through the word "compare", and agent_compare is not built (see 3.6).
  • A Screener-only question still goes through a full model loop. "Show me NIFTY 50 stocks with PE RSI OPM NPM" took 103 s because the model re-types a 50-row table. An unmatched typo ("OMP" for OPM) comes back from the tool as an "unknown metric" message. A question seen stuck on "Working..." in the web app is not yet explained: the log showed no error and no usage row for it.
  • RSI-only screens ("which stocks have RSI above 70") go to technical, whose tools have no all-stock RSI screen, so the Screener tool is not reached.
  • No timeout on an MCP tool call and no progress text while a long answer runs. The page shows only "Working...".
  • Guardrails and the prompt enhancer sit before the router in the design but are not built (section 12).

3.7 News agent, parallel mode and the "Tools used" invoke lines (built 26 Nov)

News agent. agent_news.py is an independent agent with its own class and loop (12 steps at most, plus the shared Budget). It is not a TechnicalAgent. Only the router (single-topic question) and the research analyst (a mixed question that asks for news) call it. Its tools live in the news MCP server (mcp_news.py):

ToolWhat it doesModel?
news_search(stock, days, limit)Headlines that name one Nifty 50 stock (company name matched through an alias table of all 50 stocks), newest first, one story once, at most 4 per siteno
news_sentiment(stock, days)Labels up to 12 of those headlines positive, negative or neutral with gateway role sentiment (default gemma4:12b); code adds up the counts; a missing label is counted "unlabelled", never guessedone call
news_market(days, limit)Latest market headlines with no stock namedno
  • Sources: 10 RSS feeds from 5 sites: Economic Times (6 feeds), Mint, Business Standard, Hindu BusinessLine, NDTV Profit. Headlines only (title, source, date, link); no article page is downloaded. Feeds are cached for 15 minutes; a failed feed is named in the answer and the others still answer. Live-blog and price-page titles ("Share Price Highlights", "Stock Price History", "Share Price Today", "Live Updates") are dropped.
  • Left out: Moneycontrol (newest item April 2024), Financial Express (invalid XML), Zee Business (HTTP 403), Google News (price-page spam), NSE announcements API (HTTP 301). The terms of use of the five sites were not reviewed.
  • Measured (26 Nov, gemma4:12b, real feeds): single-topic news question 20 to 40 s with one tool call; a combined RSI and news question through the analyst 42 s. Only 1 to 4 headlines per stock come back, because the feeds are general market feeds. Sentiment accuracy is not measured: three models agreed on 9 to 10 of 12 headlines, which says nothing about being right.
  • Analyst: with a news agent the split prompt may return a third part, news, only when the user asks about news. The merge adds extra rules (headlines only, no price move claimed from a headline) only when a news answer exists.

Parallel mode (off by default). Admin → Agents tab holds one checkbox: run the technical and fundamental agents at the same time. answer() reads the setting agents before every mixed question, so a change needs no restart. Budget has a lock and per-thread depth; the gateway keeps its last cost per thread. Measured once: "Compare TCS with INFY" took 187.5 s one after the other and 188.1 s in parallel (6 against 8 model calls, 20,163 against 45,533 tokens; one run each, the model chose different tools). No speed-up on this Mac; probably Ollama serves one request at a time, not confirmed. Worth testing again on a provider that serves requests side by side.

4.3 A document question (RAG search at run time)

Question such as "What risks does Reliance's annual report mention?" routes to documents, so agent_fundamental runs

↓

Model node (gemma4:12b, role chat) chooses rag_search_documents(query, symbol, doc_type, year, top_k)

↓ MCP call into the fundamentals server process

Documents.search() checks the symbol, the document type and top_k (maximum 10)

↓

gateway.embed(role="embedding") turns the query into a 768-number vector with nomic-embed-text through Ollama

↓

Chroma similarity search in the complete collection ollama_local-nomic-embed-text-page-c1000-o150, filtered by symbol, type and year

↓

Score cutoff 0.65: matches below it are treated as "not found". Each kept passage is cut to 900 characters and carries file name and page.

↓ passages returned to the model node

gemma4:12b writes the answer in its own words, cites file and page, and takes no numbers from the passages. Numbers come from fsa_* tools.

4.5 Switching provider (no code change)

↓

4.8 Cost of a model call and the daily cap

Any caller asks the gateway for a role (chat, embedding...)

↓

Gateway reads the role's provider and model. If the provider is external and the daily cap is set and already spent, it raises "daily cost cap reached" and the call is not made. Local calls are never blocked.

↓

Provider adapter makes the call and returns the answer with tokens in and out

↓

Local provider, no rate
cost 0
Rate found
cost = tokens times the rate, split into in, out and total
External provider, no rate
cost unknown (cost_known = false), never guessed

↓

One usage row is written with tokens, cost columns and the parent call id. The request's Budget adds the cost and stops the loop if a per-request cost limit is set.

Rates and the cap live in settings.sqlite and every change is audited. Part 2 will add the Admin tab (totals by day, role, model and agent, a what-if table, the call tree, and editors for the cap and rates). Part 3 (Langfuse) will be optional and off unless keys are set.

12. Guardrails: status

Admin → Guardrails tab (built 26 Nov, guardrail_rules.py). It lists every guardrail with its timing (input: before an agent runs; prompt: in the agent's instructions; tool: inside a tool; output: on the finished answer), its strength (hard: plain code the model cannot talk past; soft: a request the model can ignore), its state (built or planned) and whether it is locked. Built-in rows are read-only: this version has no on/off switch for any of them (G1, G7 and G8 are marked locked for when switches exist). You can add and remove custom rules, and turn each one on or off with a checkbox:

  • Keyword rule: words or phrases looked for in the question, before routing. Action block (no agent or model is called; the user sees the rule text) or warn (the answer goes through with a note). Whole-word, case-insensitive match. Hard, but it only catches the words you type.
  • Prompt rule: one sentence added to the technical, fundamental, news, portfolio and analyst-merge prompts. Soft: the model can ignore it. Not applied to the analyst's split call.
  • At most 30 custom rules. Ids C1, C2... are never reused. Removing a rule is allowed for custom rules only; every change is in the Change log. A change applies to the next question with no restart.
  • Event log (table guardrail_events in the settings database; this is item P6): one row each time a keyword rule fires, with a 120-character summary of the question. The tab shows how many times each rule fired and the last 50 events. It logs custom rules only: the built-in portfolio rules do not write events yet.

GUARDRAIL ALERT label (built 26 Nov, row A8). When a tool refuses a stock outside the Nifty 50 or a portfolio size outside 4 to 6, when a portfolio rule G1 to G6 blocks or warns, or when a custom rule fires, the answer starts with GUARDRAIL ALERT: and the rule. Plain code adds it from the tool result (read before it is cut to 6000 characters), so the model cannot leave it out or reword it. Gap: the alert is shown at the top but does not stop the extra tool calls. "Analyze Adani GAS" still runs both specialists first; the check before routing (P1) and the router typo "postfolio" are not built.

Not checked. The tab was tested with Streamlit's test harness and printed back (tables, checkboxes, buttons all present) but not opened in a browser, so how it looks is unknown. The 17 planned rows (P1 to P5, P7 to P18) are the review of 26 Nov; none is built. A keyword rule does not understand meaning: "target price" is not caught by a rule for "price target" unless both are listed.
