AI gateway (gateway.py, model_settings.py, providers.py). Callers name a role (chat, router, embedding, summary, judge), never a provider or model. The gateway reads the saved settings on every call, picks the provider, retries once, counts tokens, works out the cost, times the call and writes the usage row. External API (off)
Generic OpenAI-compatible adapter. For the UpGrad API once its format is known. Mocked-HTTP tests only.

Principles that the code enforces. (1) Numbers come from tools (DuckDB, Excel data), never from the model and never from vector similarity. (2) An agent that answers without calling any tool is reminded once, then replaced by a "no tool data" message. (3) Every document-based answer cites file and page. (4) A collection is searched only after it is marked complete. (5) Nothing is deleted: old files are kept under versioned names, and the UI has no delete button. (6) The research analyst may not add a number or a page citation that neither specialist gave. (7) A rate is never guessed: an external call with no rate is shown as unpriced.

4.2 The agent loop (same for the technical and fundamental agents)

Start: build the system prompt, add the question, create a Budget (12 model calls, 20 tool calls, 40,000 tokens, depth 3; the analyst uses one shared budget of 24, 40 and 80,000; a cost limit exists but is off for local models)

↓

Model node: gateway.chat(role="chat", messages, tools) goes to gemma4:12b through Ollama. The model returns tool calls or text.

↓

Tool calls returned
go to the tool node
Text returned, tools already used
final answer
Text returned, no tool ever used
reminder message once, then loop back to the model node. A second miss gives the fixed "no tool data" answer.

↓ tool calls

Tool node (LangGraph ToolNode): checks arguments, takes one unit from the tool budget, calls the MCP server. A bad tool name or argument goes back to the model as an error message, not a crash. Tool results are cut to 6,000 characters.

↓ tool results added to the messages, then back to the model node

Stop conditions: model-call, tool-call or token limit reached (the answer says what stopped it), or the model answers in text

4.3 A document question (RAG search at run time)

Question such as "What risks does Reliance's annual report mention?" routes to documents, so agent_fundamental runs

↓

Model node (gemma4:12b, role chat) chooses rag_search_documents(query, symbol, doc_type, year, top_k)

↓ MCP call into the fundamentals server process

Documents.search() checks the symbol, the document type and top_k (maximum 10)

↓

gateway.embed(role="embedding") turns the query into a 768-number vector with nomic-embed-text through Ollama

↓

Chroma similarity search in the complete collection ollama_local-nomic-embed-text-page-c1000-o150, filtered by symbol, type and year

↓

Score cutoff 0.65: matches below it are treated as "not found". Each kept passage is cut to 900 characters and carries file name and page.

↓ passages returned to the model node

gemma4:12b writes the answer in its own words, cites file and page, and takes no numbers from the passages. Numbers come from fsa_* tools.

4.4 Building the document index (offline, one-off)

bin/rag_build_bg.sh starts rag_build.py in the background. Log in runtime/logs/rag_build.log.

↓

Pick files per stock: all transcripts, latest 3 annual reports, latest 5 presentations (options change this). Skip files already marked done.

↓

rag_chunker.py (PyMuPDF): one chunk never crosses a page. Size 1,000 characters, overlap 150. Pages with no text are counted.

↓

gateway.embed(role="embedding") with nomic-embed-text in batches

↓

Write chunks to Chroma (one collection per embedding model and chunk setting). Record each file in rag_ingest.sqlite.

↓

When all 50 stocks are processed with no failed file, mark the collection complete. Only then does search use it.

4.5 Switching provider (no code change)

Admin view, Models panel: choose provider, model and parameters for a role. A separate "Test connection" button makes one small call to check the role. The change is saved to settings.sqlite with an audit row.

↓

Next gateway call reads the new setting. Agents and RAG code are unchanged. The key comes from an environment variable and is never stored or logged.

↓

If the embedding role changes, old vectors no longer match. A new collection must be built and finished before search switches to it. The old one is kept.

Router returns both: for example "Revenue growth and RSI of ITC", "Compare TCS and INFY", or an open request such as "Is TCS a good stock to buy"

↓

Split call (chat, gemma4:12b): returns a technical part and a fundamental part as JSON (fenced JSON accepted). The fundamental part is asked to cover growth, margins, ROE, valuation and documents.

↓

JSON readable
each specialist gets only its own part
JSON unreadable
both specialists get the whole question plus an "answer only your half" note
Only one part needed
that specialist answers and the merge call is skipped

↓ the specialists run one after the other on one shared budget (24 model calls, 40 tool calls, 80,000 tokens)

agent_technical then agent_fundamental, each running the loop in 4.2. A stopped or failed specialist does not stop the other: its half reads "Not available".

↓

Merge call (chat, gemma4:12b): one answer from the two labelled answers. For a "should I buy" question it says it cannot advise and lists evidence for and against.

↓

Number check
a number no specialist gave makes the answer fall back to the two labelled specialist answers, with a note
Citation check
strip_unsupported_citations removes bracketed page citations no specialist gave

Measured on the Mac with gemma4:12b: "Revenue growth and RSI of ITC" 59 s, "Compare TCS and INFY" 82 s, "Is TCS a good stock to buy" 136 s. Not yet tested live: the unreadable-split fallback and the stopped-specialist path (scripted tests cover both). The full "Is TCS a good stock to buy" answer was not read to the end after the last prompt fixes.

4.8 Cost of a model call and the daily cap

Any caller asks the gateway for a role (chat, embedding...)

↓

Gateway reads the role's provider and model. If the provider is external and the daily cap is set and already spent, it raises "daily cost cap reached" and the call is not made. Local calls are never blocked.

↓

Provider adapter makes the call and returns the answer with tokens in and out

↓

Local provider, no rate
cost 0
Rate found
cost = tokens times the rate, split into in, out and total
External provider, no rate
cost unknown (cost_known = false), never guessed

↓

One usage row is written with tokens, cost columns and the parent call id. The request's Budget adds the cost and stops the loop if a per-request cost limit is set.

Rates and the cap live in settings.sqlite and every change is audited. Part 2 will add the Admin tab (totals by day, role, model and agent, a what-if table, the call tree, and editors for the cap and rates). Part 3 (Langfuse) will be optional and off unless keys are set.
